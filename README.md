# Подборка вин

Приложение берет обученный в ноутбуке пайплайн `StandardScaler` + `LogisticRegression` и показывает, как меняется подборка хороших вин при разном пороге. Модель внутри приложения не обучается, она только загружается из `model.joblib`.

## Запуск

Python 3.12 (проверялось на 3.12.5). Команды выполняются из папки, в которой лежит `app.py`.

Windows, PowerShell:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

Если PowerShell откажется выполнять `Activate.ps1` из-за политики запуска скриптов, разреши ее для текущего окна командой `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` и повтори активацию.

macOS и Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Приложение откроется на http://localhost:8501.

## Вкладки

**Оценка вина.** Двенадцать полей с результатами анализа, границы и значения по умолчанию взяты из `test.csv` (минимум, максимум, медиана). Приложение показывает вероятность того, что вино хорошее, и решение модели при пороге из сайдбара.

**Модельные метрики.** Матрица ошибок, precision, recall и F1 на тестовой выборке, ROC- и PR-кривые с отмеченной текущей рабочей точкой. Все пересчитывается при движении слайдера порога.

**Пакетное предсказание.** Загрузка CSV с признаками вин без колонки `target`, таблица с вероятностью и решением, выгрузка результата. Если в файле не хватает колонок, приложение называет недостающие и не падает.

**Что выучила модель.** Коэффициенты логистической регрессии после стандартизации, отсортированные по значению.

## Про кэширование

`st.cache_resource` используется для модели: декоратор держит один объект на весь сервер, не копирует его между сессиями и не пытается сериализовать. Для неизменяемого тяжелого объекта, например обученного пайплайна, это лучшее решение.

`st.cache_data` используется для `test.csv`, конфига и вероятностей на тесте. Он возвращает копию результата на каждый вызов. Если пользователь изменит полученный датафрейм, кэш не испортится.

Без декоратора `joblib.load` вызывался бы при каждом перезапуске скрипта, те на каждое движение слайдера модель заново читалась бы с диска. То же самое с `predict_proba` на тестовой выборке: вероятности от порога не зависят, но пересчитывались бы при каждом действии пользователя.

Аргумент `_model` в `test_proba` назван с подчеркиванием, чтобы Streamlit не пытался его хешировать.
